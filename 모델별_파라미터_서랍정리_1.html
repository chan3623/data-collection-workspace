모델마다 서랍이 다르다

모델을 바꿀 때마다 신경 써야 할 파라미터 전체가 늘어나는 게 아니라, 그 모델의 서랍 하나만 열면 된다. 다른 서랍(솔버, 활성함수, 트리 개수 등)은 애초에 이 모델과 상관없는 것들이다.

각 파라미터마다 실전에서 자주 쓰는 예시값도 같이 넣었고, 마지막엔 Pipeline + GridSearchCV로 이 값들을 자동 탐색하는 방법도 정리했다.

회귀·선형 거리기반 확률기반 트리·앙상블 신경망 Pipeline·GridSearch

회귀 · 선형 계열

Linear Regression

회귀

특성과 타깃 사이의 직선 관계를 찾는 가장 기본적인 회귀 모델.

LinearRegression()
파라미터의미예시값
fit_intercept절편(y절편) 학습 여부True (기본)

건드릴 파라미터가 사실상 거의 없음. 과적합 방지가 필요하면 아래 Ridge/Lasso로 넘어가는 게 정석.

Ridge / Lasso

회귀

Linear Regression에 규제(정규화)를 더해 과적합을 억누르는 버전.

Ridge(alpha=1.0) Lasso(alpha=1.0)
파라미터의미예시값
alpha규제 강도. 클수록 계수를 더 강하게 누름0.01, 0.1, 1, 10

Ridge는 계수를 0에 가깝게, Lasso는 아예 0으로 만들어 특성 선택 효과도 있음. 솔버/활성함수 해당 없음.

Logistic Regression

분류

시그모이드로 출력을 0~1 확률로 바꿔서 분류하는 선형모델.

LogisticRegression( C=1.0, penalty='l2', solver='lbfgs', max_iter=1000 )
파라미터의미예시값
C규제 강도. 작을수록 규제 강함0.01, 0.1, 1, 10, 100
penalty규제 종류'l1', 'l2', 'elasticnet'
solver최적화 알고리즘. penalty에 따라 지원 여부 다름'lbfgs', 'liblinear'
max_iter최대 반복 횟수1000, 5000

활성함수는 시그모이드 하나로 고정이라 고민 대상이 아님. 트리 개수, 지니 불순도 해당 없음.

거리 기반

KNN

분류·회귀

가까운 K개 이웃을 보고 다수결(분류) 또는 평균(회귀)으로 예측.

KNeighborsClassifier( n_neighbors=5, weights='uniform', metric='euclidean' )
파라미터의미예시값
n_neighbors이웃 개수(K)3, 5, 7, 9, 11
weightsuniform / distance'uniform', 'distance'
metric거리 계산 방식'euclidean', 'manhattan'
p민코프스키 거리 지수. 1=맨하탄, 2=유클리디안1, 2

학습 과정 자체가 없음(lazy learning) — 반복횟수, 깊이 등 학습 관련 파라미터가 아예 존재하지 않음. 스케일링은 필수.

SVM

분류·회귀

마진을 최대화하는 경계를 찾는 모델. 커널트릭으로 비선형도 처리.

SVC( C=1.0, kernel='rbf', gamma='scale' )
파라미터의미예시값
C규제 강도. 작을수록 마진을 넓게0.1, 1, 10, 100
kernel데이터가 나뉘는 형태에 맞는 커널'linear', 'rbf', 'poly'
gammarbf 커널의 곡률. 클수록 복잡한 경계'scale', 0.01, 0.1, 1

트리 개수, 지니 불순도, 활성함수 모두 해당 없음. 스케일링 필수.

확률 기반

Naive Bayes

분류

베이즈 정리 + 각 특성이 독립이라는 가정으로 빠르게 확률 계산.

GaussianNB(var_smoothing=1e-9)
파라미터의미예시값
var_smoothing분산에 작은 값을 더해 수치 안정성 확보1e-9, 1e-8, 1e-7

파라미터가 사실상 거의 없어서 가장 튜닝 부담이 적은 모델. 트리·거리·신경망 관련 파라미터 전부 해당 없음.

LDA

분류

클래스 간 분산은 최대화, 클래스 내 분산은 최소화하는 방향으로 투영.

LinearDiscriminantAnalysis( solver='svd', shrinkage=None )
파라미터의미예시값
solver계산 방식'svd', 'lsqr', 'eigen'
shrinkage공분산 추정 안정화. lsqr/eigen에서만 사용'auto', 0.1~0.9

여기 나오는 solver는 로지스틱회귀의 solver와 이름만 같을 뿐 완전히 다른 개념 — 헷갈리지 않게 주의.

트리 · 앙상블 계열

Decision Tree

분류·회귀

조건으로 데이터를 계속 쪼개서 규칙을 만드는 모델.

DecisionTreeClassifier( criterion='gini', max_depth=5, min_samples_split=10 )
파라미터의미예시값
criterion분기 기준'gini', 'entropy'
max_depth트리 최대 깊이3, 5, 10, None
min_samples_split노드 분할 최소 샘플 수2, 5, 10, 20
min_samples_leaf리프 노드 최소 샘플 수1, 5, 10

스케일링 불필요. 솔버·활성함수 해당 없음.

Random Forest

분류·회귀

결정트리 여러 개를 무작위로 만들어 다수결(분류)·평균(회귀)으로 합치는 배깅.

RandomForestClassifier( n_estimators=100, max_depth=10, max_features='sqrt', criterion='gini' )
파라미터의미예시값
n_estimators트리 개수100, 200, 500
max_depth각 트리의 최대 깊이5, 10, 20, None
max_features분기마다 무작위로 볼 특성 개수'sqrt', 'log2', 0.5
min_samples_splitDecision Tree와 동일2, 5, 10
oob_score자체 검증 점수 계산 여부True / False

Decision Tree 파라미터를 그대로 물려받고 앙상블용 파라미터만 추가됨. 솔버·활성함수 해당 없음.

XGBoost / LightGBM

분류·회귀

트리를 순차적으로 이어붙이며 이전 오차를 보완하는 부스팅.

XGBClassifier( n_estimators=200, max_depth=6, learning_rate=0.1, subsample=0.8 )
파라미터의미예시값
learning_rate가장 중요. n_estimators와 트레이드오프0.01, 0.05, 0.1, 0.3
n_estimators부스팅 단계(트리) 개수100, 300, 500, 1000
max_depthRF보다 보통 얕게 잡음3, 5, 6, 8
subsample각 트리 학습에 쓸 데이터 비율0.6, 0.8, 1.0
colsample_bytree각 트리 학습에 쓸 특성 비율0.6, 0.8, 1.0

RF보다 튜닝 부담이 더 큼 — learning_rate와 n_estimators를 세트로 조절하는 게 핵심.

신경망 계열

MLPClassifier

분류·회귀

입력층-은닉층-출력층 구조의 다층 퍼셉트론. 유일하게 활성함수·솔버가 등장하는 모델.

MLPClassifier( hidden_layer_sizes=(100,), activation='relu', solver='adam', alpha=0.0001, max_iter=1000 )
파라미터의미예시값
hidden_layer_sizes은닉층 구조(100,), (100,50), (64,32)
activation활성화 함수'relu', 'tanh', 'logistic'
solver최적화 알고리즘'adam', 'sgd', 'lbfgs'
alphaL2 정규화 강도(C와 반대 방향)0.0001, 0.001, 0.01
max_iter최대 반복(epoch) 횟수500, 1000, 2000

솔버·활성함수는 이 서랍에만 있는 개념. 기본값(relu + adam)이면 웬만한 상황에서 무난하게 작동함.

Pipeline · GridSearchCV

왜 Pipeline을 쓰나

지금까지 전처리(스케일링·인코딩)와 모델 학습을 따로따로 코드로 짰는데, 이걸 하나로 묶어서 "전처리 → 모델" 순서를 고정된 하나의 객체로 만드는 게 Pipeline이다. train에만 fit, test는 transform만 하는 규칙도 Pipeline이 자동으로 지켜준다 — data leakage를 원천 차단하는 효과가 있다.

from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.ensemble import RandomForestClassifier

pipe = Pipeline([
    ('scaler', StandardScaler()),
    ('model', RandomForestClassifier(random_state=42))
])

pipe.fit(X_train, y_train)          # scaler.fit_transform + model.fit 순서대로 자동 실행
pipe.predict(X_test)                 # scaler.transform + model.predict 순서대로 자동 실행

핵심: pipe.fit(X_train, y_train) 한 줄이면, 내부적으로 scaler는 train으로만 fit되고 그 다음 model이 학습됨. test에 predict할 때도 scaler.transform이 자동으로 먼저 적용됨. 저번에 계속 강조한 "train만 fit_transform, test는 transform" 규칙을 실수할 여지 자체가 없어짐.

수치형 · 범주형을 함께 — ColumnTransformer

한 데이터셋에 수치형과 범주형이 섞여 있으면, 각각 다른 전처리(스케일링 vs 인코딩)를 적용해야 한다. ColumnTransformer로 컬럼별 처리를 나눠서 Pipeline 안에 넣는다.

from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import StandardScaler, OneHotEncoder

num_cols = ['age', 'income']
cat_cols = ['gender', 'region']

preprocessor = ColumnTransformer([
    ('num', StandardScaler(), num_cols),
    ('cat', OneHotEncoder(handle_unknown='ignore'), cat_cols)
])

pipe = Pipeline([
    ('preprocessor', preprocessor),
    ('model', RandomForestClassifier(random_state=42))
])

pipe.fit(X_train, y_train)

handle_unknown='ignore'는 test에 train에서 못 본 범주가 나와도 에러 없이 넘어가게 해주는 안전장치. 실무에서 거의 항상 켜두는 옵션이다.

GridSearchCV — Pipeline 안의 파라미터까지 자동 탐색

위 표에서 정리한 "예시값" 후보들을 사람이 하나씩 손으로 바꿔가며 돌려보는 대신, GridSearchCV가 모든 조합을 자동으로 다 시도하고 교차검증까지 해서 최적값을 찾아준다. Pipeline 안에 있는 모델 파라미터는 모델이름__파라미터명 형태로 접근한다.

from sklearn.model_selection import GridSearchCV

param_grid = {
    'model__n_estimators': [100, 200, 300],
    'model__max_depth': [5, 10, 20, None],
    'model__max_features': ['sqrt', 'log2']
}

grid = GridSearchCV(
    pipe, param_grid,
    cv=5, scoring='f1', n_jobs=-1
)
grid.fit(X_train, y_train)

print(grid.best_params_)   # 가장 좋았던 조합
print(grid.best_score_)    # 그때의 교차검증 점수
best_model = grid.best_estimator_   # 최적 파라미터로 재학습된 최종 파이프라인

'model__n_estimators'처럼 이름 앞에 파이프라인 단계명(여기선 'model')을 붙이는 이유: Pipeline 안에 여러 단계가 있어서, GridSearchCV가 "어느 단계의 어떤 파라미터를 바꿀지" 구분해야 하기 때문이다. 전처리 단계(preprocessor)의 파라미터도 똑같이 'preprocessor__num__...' 식으로 접근 가능하다.

탐색 공간이 넓으면 — RandomizedSearchCV

파라미터 후보가 많아지면(예: XGBoost처럼 파라미터가 5개 이상) GridSearchCV는 모든 조합을 다 시도하느라 조합 수가 기하급수적으로 늘어난다. 이럴 땐 무작위로 일부 조합만 뽑아서 시도하는 RandomizedSearchCV가 훨씬 빠르다.

from sklearn.model_selection import RandomizedSearchCV

param_dist = {
    'model__n_estimators': [100, 200, 300, 500],
    'model__max_depth': [3, 5, 6, 8, 10],
    'model__learning_rate': [0.01, 0.05, 0.1, 0.3]
}

search = RandomizedSearchCV(
    pipe, param_dist,
    n_iter=20, cv=5, scoring='f1',
    random_state=42, n_jobs=-1
)
search.fit(X_train, y_train)

n_iter=20이면 가능한 모든 조합이 수백 개여도 그중 20개만 무작위로 뽑아서 시도한다. GridSearchCV보다 최적값을 놓칠 순 있지만, 훨씬 빠르게 "그럭저럭 좋은" 조합을 찾을 수 있다.

기억할 것

모델을 바꿀 때마다 신경 쓸 파라미터가 계속 쌓이는 게 아니다. 지금 쓰는 모델의 서랍 하나만 열면 되고, 그 서랍 안 값들을 하나씩 손으로 바꿔볼 필요도 없다 — Pipeline에 담아서 GridSearchCV에 넘기면 조합 탐색은 컴퓨터가 대신 해준다.
