SKN AI 35기 · 머신러닝 종합 학습 노트

머신러닝 전체를 한 장의 지도처럼

모델 이름을 외우는 것보다 중요한 것은 어떤 문제에 어떤 모델을 쓰고, 어떤 전처리가 필요하며, 어떤 하이퍼파라미터가 모델의 복잡도와 성능을 바꾸는지 연결해서 이해하는 것이다.

지금까지 공부한 회귀·분류·스케일링·차원축소·특성선택·앙상블·신경망·군집화·평가·튜닝을 모델별 서랍으로 나눴다. 각 서랍에는 목적, 주요값, 값의 방향, 스케일링 필요 여부를 함께 정리했다.

전체 흐름 전처리 선형·회귀 거리·SVM 트리·앙상블 신경망 비지도학습 평가 튜닝

01 · 머신러닝 전체 흐름

실전 기본 순서

데이터 확인
  ↓
결측치 / 이상치 / 중복 / 타입 확인
  ↓
X(특성) / y(타깃) 분리
  ↓
Train / Test 분리
  ↓
전처리
  ├─ 결측치 처리
  ├─ 범주형 인코딩
  └─ 스케일링
  ↓
Feature Selection / PCA (필요한 경우)
  ↓
Baseline 모델
  ↓
Cross Validation
  ↓
하이퍼파라미터 튜닝
  ↓
최종 Test 평가

핵심: Test 데이터는 최종 평가용으로 최대한 건드리지 않는다. Scaling, PCA, Feature Selection처럼 데이터를 학습하는 전처리는 Train에만 fit하고 Test에는 transform만 적용해야 한다.

지도학습

X → y

정답 y가 존재한다. 예측해야 할 값이 범주인지 숫자인지에 따라 분류와 회귀로 나뉜다.

문제 대표 모델 예시
분류 Logistic, KNN, Tree, SVM, RF, XGBoost, LightGBM, MLP 생존 / 사망
회귀 Linear, Polynomial, Tree, KNN, SVR, RF, XGBoost, LightGBM, MLP 가격 / 점수

비지도학습

X만 존재

정답 y 없이 데이터의 구조를 찾는다.

목적 방법 핵심
군집화 K-Means, Hierarchical, DBSCAN 비슷한 데이터 그룹
차원축소 PCA 정보 유지 + 차원 감소

02 · 전처리 · 스케일링 · 특성선택 · 차원축소

StandardScaler

스케일링

평균 0, 표준편차 1을 기준으로 특성의 크기를 맞춘다.

z = (x - μ) / σ
항목 목적 주요값
fit Train의 평균·표준편차를 학습 X_train
transform 학습한 기준으로 데이터 변환 X_train / X_test

KNN, SVM, Logistic, MLP, PCA처럼 거리·최적화·분산에 영향을 받는 모델에서 특히 중요. Tree 계열은 보통 불필요.

MinMaxScaler

스케일링

각 특성을 지정한 범위로 압축한다. 기본 범위는 0~1.

x' = (x - min) / (max - min)
항목 목적 주요값
feature_range 변환할 최소·최대 범위 (0,1), (-1,1)

이상치가 있으면 min/max 자체가 영향을 받는다. 범위를 일정하게 만들고 싶을 때 유용하다.

RobustScaler

스케일링

평균·표준편차 대신 중앙값과 IQR을 사용해 이상치의 영향을 줄인다.

x' = (x - median) / IQR
항목 목적 주요값
quantile_range IQR을 계산할 분위수 범위 (25,75)

이상치가 많은 연속형 데이터에서 StandardScaler의 대안으로 고려한다.

One-Hot Encoding

인코딩

순서가 없는 범주형 값을 0/1 컬럼으로 변환한다.

파라미터 의미 주요값
handle_unknown Test에 처음 보는 범주가 등장했을 때 처리 'ignore'
drop 더미 변수 하나를 제거할지 결정 None, 'first'

Pipeline + ColumnTransformer와 함께 사용하면 Train/Test 전처리 불일치를 줄일 수 있다.

Feature Selection

차원 감소

원본 Feature 중 유용한 컬럼을 선택한다. PCA처럼 새 축을 만드는 것과 다르다.

방법 목적 핵심
Correlation 타깃 또는 Feature 간 관계 확인 상관계수
Feature Importance Tree 계열의 중요도 활용 상위 K개
SelectKBest 통계적 점수가 높은 K개 선택 k=10,20...

PCA

차원축소

원본 Feature를 버리는 것이 아니라 분산을 최대한 보존하는 새로운 주성분 축으로 압축한다.

PCA(n_components=2)
파라미터 의미 주요값
n_components 남길 주성분 개수 또는 보존할 분산 비율 2, 5, 0.90, 0.95
whiten 주성분을 추가로 정규화 False / True

보통 Scaling → PCA 순서. PCA는 Feature의 스케일에 영향을 받는다. n_components=0.95처럼 분산 보존율로 지정할 수도 있다.

03 · 선형 · 회귀 계열

Linear Regression

회귀

특성과 타깃 사이의 선형 관계를 찾는다.

LinearRegression(fit_intercept=True)
파라미터 의미 주요값
fit_intercept 절편을 학습할지 결정 True / False

튜닝할 값이 거의 없다. 과적합을 제어하고 싶다면 Ridge/Lasso 같은 규제 모델을 고려한다.

Polynomial Regression

회귀

PolynomialFeatures로 기존 Feature를 제곱·세제곱 등 확장해 곡선 관계를 표현한다.

PolynomialFeatures(degree=2)
파라미터 의미 주요값
degree 다항식 차수. 높을수록 복잡 2, 3, 4
include_bias 상수항 컬럼을 추가할지 결정 True / False

degree가 높아지면 Feature 수가 빠르게 증가해 과적합 가능성이 커진다.

Ridge / Lasso

회귀

선형 회귀에 규제를 추가한다. Ridge는 계수를 작게 만들고 Lasso는 일부 계수를 0으로 만들 수 있다.

Ridge(alpha=1.0) Lasso(alpha=1.0)
파라미터 의미 주요값
alpha 규제 강도. 클수록 강한 규제 0.01, 0.1, 1, 10, 100

SVR

회귀

SVM의 회귀 버전. 일정 오차 범위 안의 예측은 허용하고 그 바깥의 오차를 줄인다.

SVR(C=1.0, epsilon=0.1, kernel='rbf')
파라미터 의미 주요값
C 규제 정도. 작을수록 더 단순 0.1, 1, 10, 100
epsilon 오차 허용 튜브 폭 0.01, 0.1, 0.2
kernel 경계/관계의 형태 'linear','rbf','poly'
gamma RBF 영향 범위. 클수록 복잡 'scale',0.01,0.1,1

KNN과 마찬가지로 거리 기반 성격이 있어 스케일링이 중요하다.

04 · 거리 기반 · 마진 기반

KNN

분류·회귀

새 데이터 주변의 가까운 K개를 확인해 분류는 다수결, 회귀는 평균 등으로 예측한다.

KNeighborsClassifier( n_neighbors=5, weights='uniform', metric='euclidean' )
파라미터 목적 주요값
n_neighbors 참고할 이웃 수. 작을수록 복잡 3,5,7,9,11
weights 이웃의 영향력 계산 'uniform','distance'
metric 거리 계산 방식 'euclidean','manhattan'
p Minkowski 거리 지수 1=Manhattan, 2=Euclidean

스케일링 중요. 학습 파라미터를 많이 가지지 않는 lazy learning 모델이다.

SVM / SVC

분류·회귀

클래스 사이의 Margin을 최대화하는 경계를 찾고 Kernel을 통해 비선형 관계를 표현한다.

SVC(C=1.0, kernel='rbf', gamma='scale')
파라미터 목적 주요값
C 오분류에 대한 벌점. 클수록 복잡해지기 쉬움 0.01,0.1,1,10,100
kernel 선형/비선형 경계 방식 'linear','rbf','poly'
gamma RBF에서 한 데이터의 영향 범위 'scale',0.001,0.01,0.1,1
degree poly kernel의 차수 2,3,4

C ↑, gamma ↑는 일반적으로 더 복잡한 경계를 만들 수 있다. 스케일링 필수에 가까움.

05 · 확률 · 선형 분류

Logistic Regression

분류

선형 결합을 sigmoid로 0~1 확률로 변환해 분류한다. Titanic의 생존 확률 예측처럼 확률을 직접 보고 싶을 때 특히 이해하기 좋다.

LogisticRegression( C=1.0, penalty='l2', solver='lbfgs', max_iter=1000 )
파라미터 목적 주요값
C 규제의 역수. 작을수록 규제 강함 0.01,0.1,1,10,100
penalty 규제 방식 'l1','l2','elasticnet'
solver 최적화 알고리즘. penalty와 호환성 확인 'lbfgs','liblinear','saga'
max_iter 최대 반복 횟수 500,1000,5000

예측 확률은 predict_proba()로 확인할 수 있다. 스케일링을 적용하면 최적화가 안정적이다.

Naive Bayes

분류

Bayes 정리와 특성 간 조건부 독립 가정을 이용한다. 빠르고 파라미터가 적다.

GaussianNB(var_smoothing=1e-9)
파라미터 목적 주요값
var_smoothing 작은 값을 분산에 더해 수치 안정성 확보 1e-9,1e-8,1e-7

GaussianNB는 연속형 특성에 많이 사용. 모델 자체의 튜닝 부담이 작다.

LDA

분류

클래스 간 분산은 크게, 클래스 내부 분산은 작게 만드는 투영 방향을 찾는다.

LinearDiscriminantAnalysis( solver='svd', shrinkage=None )
파라미터 목적 주요값
solver 계산 방법 'svd','lsqr','eigen'
shrinkage 공분산 추정 안정화. 일부 solver에서 사용 'auto', 0.1~0.9

06 · 트리 · 앙상블 계열

Decision Tree

분류·회귀

조건을 반복해서 데이터를 나누며 규칙 기반의 예측 구조를 만든다.

DecisionTreeClassifier( criterion='gini', max_depth=5, min_samples_split=10 )
파라미터 목적 주요값
criterion 분할의 품질을 판단 'gini','entropy','log_loss'
max_depth 최대 깊이. 클수록 복잡 3,5,10,None
min_samples_split 노드를 나누기 위한 최소 샘플 수 2,5,10,20
min_samples_leaf Leaf 최소 샘플 수. 클수록 보수적 1,2,5,10

스케일링 불필요. max_depth를 무제한으로 두면 데이터에 지나치게 맞춰질 수 있다.

Random Forest

분류·회귀

여러 Decision Tree를 독립적으로 만들고 결과를 결합하는 Bagging 계열 앙상블.

RandomForestClassifier( n_estimators=100, max_depth=10, max_features='sqrt' )
파라미터 목적 주요값
n_estimators Tree 개수. 많을수록 안정적이나 계산량 증가 100,200,500
max_depth 각 Tree의 최대 깊이 5,10,20,None
max_features 분할마다 고려할 Feature 수/비율 'sqrt','log2',0.5
min_samples_leaf Leaf 최소 샘플 수 1,2,5,10
oob_score Out-of-Bag 검증 점수 사용 여부 True/False

스케일링 불필요. 단일 Tree보다 일반화 성능이 안정적인 경우가 많다.

XGBoost

분류·회귀

이전 Tree의 오차를 다음 Tree가 보완하는 Gradient Boosting 계열. 지금까지 학습한 모델 중 튜닝 가치가 높은 대표 모델.

XGBClassifier( n_estimators=300, max_depth=3, learning_rate=0.1, subsample=0.8 )
파라미터 목적 주요값
n_estimators Boosting 단계/Tree 수 100,300,500,1000
learning_rate 각 Tree가 기여하는 크기. 작으면 더 많은 Tree 필요 0.01,0.05,0.1,0.3
max_depth Tree 복잡도 3,5,7,10
subsample Tree마다 사용할 데이터 비율 0.6,0.8,1.0
colsample_bytree Tree마다 사용할 Feature 비율 0.6,0.8,1.0
gamma 추가 분할에 필요한 최소 손실 감소 0,0.1,0.5,1
reg_alpha L1 규제 0,0.01,0.1,1
reg_lambda L2 규제 1,5,10
scale_pos_weight 불균형 분류에서 Positive 클래스 가중치 neg/pos 비율부터 탐색

핵심 세트: learning_rate + n_estimators + max_depth. 불균형 분류에서는 scale_pos_weight도 중요하다.

LightGBM

분류·회귀

Gradient Boosting 계열이며 Leaf-wise 성장 방식을 사용한다. 특히 num_leaves가 중요하다.

LGBMClassifier( n_estimators=300, learning_rate=0.05, num_leaves=31 )
파라미터 목적 주요값
n_estimators Tree 수 100,300,500,1000
learning_rate 학습률. 낮으면 더 많은 Tree 필요 0.01,0.05,0.1
num_leaves Tree의 Leaf 수. 클수록 복잡 15,31,63,127
max_depth Tree 최대 깊이 -1,3,5,10
min_child_samples Leaf 최소 데이터 수 10,20,50,100
subsample 사용할 데이터 비율 0.6,0.8,1.0
colsample_bytree 사용할 Feature 비율 0.6,0.8,1.0
reg_alpha L1 규제 0,0.01,0.1,1
reg_lambda L2 규제 0,1,5,10

num_leaves ↑ → 복잡도 ↑. XGBoost의 max_depth와 비슷하게 과적합 관리의 핵심 축으로 본다.

07 · 신경망 계열

MLPClassifier

분류

입력층 → 은닉층 → 출력층으로 구성되는 다층 퍼셉트론. 스케일링이 중요하다.

MLPClassifier( hidden_layer_sizes=(100,), activation='relu', solver='adam', alpha=0.0001, max_iter=1000 )
파라미터 목적 주요값
hidden_layer_sizes 은닉층 수와 각 층의 뉴런 수 (100,), (100,50), (64,32)
activation 비선형성을 추가하는 활성화 함수 'relu','tanh','logistic'
solver 가중치를 최적화하는 방법 'adam','sgd','lbfgs'
alpha L2 규제 강도 0.0001,0.001,0.01
learning_rate_init 초기 학습률 0.0001,0.001,0.01
max_iter 최대 반복 횟수 500,1000,2000

StandardScaler와 함께 사용하는 것이 일반적. max_iter를 늘리는 것은 모델을 복잡하게 만드는 것과는 다른 문제다. 수렴할 시간을 늘리는 것이다.

MLPRegressor

회귀

MLPClassifier와 구조는 비슷하지만 연속적인 숫자를 예측한다.

MLPRegressor( hidden_layer_sizes=(100,), activation='relu', solver='adam', alpha=0.0001 )
파라미터 목적 주요값
hidden_layer_sizes 네트워크 구조 (50,), (100,), (100,50)
activation 은닉층 활성화 함수 'relu','tanh'
solver 최적화 알고리즘 'adam','sgd','lbfgs'
alpha L2 규제 0.0001,0.001,0.01
learning_rate_init 학습률 0.0001,0.001,0.01

분류/회귀 모두 스케일링이 중요하다. 출력층의 목적이 다르다는 점만 먼저 구분하면 된다.

08 · 비지도학습 · 군집화

K-Means

군집화

K개의 중심점을 기준으로 가까운 데이터끼리 반복적으로 묶는다.

KMeans( n_clusters=3, init='k-means++', n_init=10 )
파라미터 목적 주요값
n_clusters 만들 군집 수 K 2,3,4,5...
init 초기 중심점 선택 방법 'k-means++','random'
n_init 서로 다른 초기 중심점으로 반복 실행 10,20,50
max_iter 한 초기화에서 최대 반복 횟수 100,300,500

거리 기반이므로 스케일링이 중요. K는 Silhouette 등으로 비교하며 선택할 수 있다.

Hierarchical Clustering

군집화

데이터를 하나씩 병합하며 계층 구조를 만들고 Dendrogram을 통해 군집 구조를 확인한다.

pdist(data, metric='cosine') linkage(distance_matrix, method='average')
파라미터 목적 주요값
metric 두 데이터 사이 거리 'euclidean','cosine','manhattan'
method 군집 간 거리 계산 방식 'single','complete','average','ward'
criterion fcluster가 군집을 자르는 기준 'distance','maxclust'
t criterion에 따른 임계값 예: 0.5 / 3

Cosine distance는 벡터의 방향 유사성을 볼 때 유용. ward는 일반적으로 Euclidean 거리 기반에서 사용한다.

DBSCAN

군집화

밀도가 높은 영역을 군집으로 묶고, 외딴 데이터는 Noise로 분류할 수 있다.

DBSCAN( eps=0.5, min_samples=5 )
파라미터 목적 주요값
eps 이웃으로 인정하는 최대 거리 0.1,0.3,0.5,1.0
min_samples 핵심 포인트가 되기 위한 최소 이웃 수 3,5,10,20
metric 거리 계산 방법 'euclidean','manhattan'

K를 미리 지정하지 않아도 되며 Noise 탐지가 가능하다. eps와 min_samples의 조합이 핵심이다.

Cosine Distance

거리

두 벡터의 방향이 얼마나 다른지를 측정한다. 텍스트·고차원 벡터처럼 크기보다 방향이 중요한 경우 자주 고려한다.

Cosine Distance = 1 - Cosine Similarity
값 의미 방향
Similarity ≈ 1 방향이 매우 유사 유사 ↑
Distance ≈ 0 거리가 매우 가까움 유사 ↑

평가 조건: 군집 평가 지표는 일반적으로 최소 2개 이상이면서 데이터 개수보다 적은 군집이 필요하다. 현재 실습처럼 정답 y가 없는 상황에서도 군집 내부/군집 간 구조를 기준으로 품질을 비교할 수 있다.

10 · Cross Validation · Pipeline · 하이퍼파라미터 튜닝

Cross Validation

Training Data
     ↓

│ Fold 1 │ Fold 2 │ Fold 3 │ Fold 4 │ Fold 5 │
└────────┴────────┴────────┴────────┴────────┘
   검증       검증       검증       검증       검증

평균 Validation Score

cv=5라면 5-Fold Cross Validation. 하나의 Train/Test Split에만 결과가 좌우되는 것을 줄이고, 하이퍼파라미터 조합을 비교할 때 더 안정적인 기준을 제공한다.

Pipeline — 전처리와 모델을 하나로

from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.svm import SVC

pipe = Pipeline([
    ('scaler', StandardScaler()),
    ('model', SVC())
])

pipe.fit(X_train, y_train)
pipe.predict(X_test)

핵심: scaler가 Train으로 fit되고 Test에서는 transform만 수행되는 흐름을 Pipeline이 관리한다. 특히 Cross Validation에서 전처리가 검증 데이터까지 미리 학습되는 Data Leakage를 막는 데 중요하다.

ColumnTransformer — 컬럼마다 다른 전처리

from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import StandardScaler, OneHotEncoder

num_cols = ['age', 'income']
cat_cols = ['gender', 'region']

preprocessor = ColumnTransformer([
    ('num', StandardScaler(), num_cols),
    ('cat', OneHotEncoder(handle_unknown='ignore'), cat_cols)
])

수치형 → Scaling, 범주형 → Encoding처럼 컬럼별로 처리 방식을 다르게 적용할 수 있다. handle_unknown='ignore'는 Test에 Train에서 보지 못한 범주가 등장해도 변환 과정에서 오류가 나는 것을 막는다.

GridSearchCV

param_grid = {
    'model__C': [0.1, 1, 10],
    'model__gamma': ['scale', 0.01, 0.1]
}

grid = GridSearchCV(
    pipe,
    param_grid,
    cv=5,
    scoring='f1',
    n_jobs=-1
)

grid.fit(X_train, y_train)

grid.best_params_
grid.best_score_
grid.best_estimator_

model__파라미터처럼 Pipeline 단계 이름을 앞에 붙인다. 예를 들어 모델 단계 이름이 model이면 model__C가 된다. scoring='f1'이면 F1이 가장 높은 조합을 찾는다.

RandomizedSearchCV

search = RandomizedSearchCV(
    pipe,
    param_distributions=param_dist,
    n_iter=20,
    cv=5,
    scoring='f1',
    random_state=42,
    n_jobs=-1
)

GridSearchCV는 모든 조합을 검사하고, RandomizedSearchCV는 지정한 횟수만큼 일부 조합을 랜덤하게 검사한다. XGBoost·LightGBM처럼 탐색 공간이 넓은 모델에서 계산량을 줄이는 데 유리하다.

12 · 과적합 / 과소적합

Overfitting

과적합

Train 데이터의 세부 패턴과 노이즈까지 지나치게 학습한 상태.

증상 대응 예
Train ↑ / Test ↓ 복잡도 감소 depth ↓
모델 너무 복잡 규제 강화 alpha ↑
Noise Feature 많음 Feature Selection 상위 K개

Underfitting

과소적합

모델이 데이터의 구조를 충분히 학습하지 못한 상태.

증상 대응 예
Train ↓ / Test ↓ 복잡도 증가 depth ↑
규제 너무 강함 규제 완화 alpha ↓
Feature 부족 유용한 Feature 추가 K ↑

기억할 것

하이퍼파라미터는 전부 외우는 대상이 아니다. 먼저 모델의 복잡도, 규제, 학습 속도, 데이터·Feature 사용량, 거리 계산, Tree 구조, 신경망 구조 중 무엇을 조절하는지 이해하면 된다. 그리고 실제 조합 탐색은 Pipeline + Cross Validation + GridSearchCV 또는 RandomizedSearchCV에 맡기면 된다.
